# Контекст проекта (передача из чата claude.ai, 2026-11-07)

## Цель
Соло-продукт без продаж и общения с заказчиками: портфель небольших платных
приложений для Jira Cloud на Atlassian Marketplace. Ориентир — $5–20k MRR.
Владелец: Даниил, senior backend (Java/Go/Kotlin), живёт во Вьетнаме,
выплаты Atlassian идут SWIFT в USD на местный счёт.

## Почему Atlassian Marketplace
- Data Center закрывается (конец подписок 30.03.2029) → компании переезжают в облако,
  у многих DC-приложений нет облачной версии.
- Connect перестаёт поддерживаться 31.01.2027 → брошенные Connect-приложения
  оставят клиентов без замены.
- 0% комиссии Atlassian для Forge-приложений до $1M суммарного дохода.

## Шорт-лист приложений (по анализу API маркетплейса)
1. Управление опциями полей админами проектов — 4 облачных конкурента, ~84 установки на всех.
2. Текстовый гаджет для дашбордов — бесплатное Labs-приложение: 7482 установки, рейтинг 3.3.
3. Восстановление удалённых задач — лидер (Bloompeak, 933 уст.) застрял на Connect.
4. Поле «последний комментарий» — ТЕКУЩЕЕ, учебное (6 конкурентов, ~370 уст.).
5. «Кто смотрит задачу» — проверить ограничения платформы до старта.
Отброшены: цвета статусов и JQL-функции (стена платформы), напоминания,
повторяющиеся задачи, Гант (тесно).

## Правила портфеля
- Общий каркас: Forge, лицензирование, шаблон документации и листинга.
- Отсечение: <~30 установок и ноль вопросов за 60 дней после релиза → заморозить.

## Текущее состояние: last-comment-field v0.3 (в репозитории, ни разу не деплоилось)
- Forge, TypeScript. Read-only `jira:customField` (string). Устройство — в README.
- v0.3, отличие от конкурентов для JSM: ещё три read-only поля, только в проектах `service_desk` —
  `last-customer-reply` (datetime), `last-agent-reply` (datetime), `last-reply-by` (string: Customer/Agent).
  Агент = право `SERVICEDESK_AGENT` в проекте (`/rest/api/3/user/permission/search`, scope `read:jira-user`),
  кэш на время тёплого контейнера; `accountType: customer` — клиент без запроса.
  Ответ = публичный комментарий человека (не `app`); `includeRestricted` не влияет.
  Время ожидания — через JQL (`"Last customer reply" <= -4h`), живого счётчика нет.
  В поле даты пишется `created` комментария как есть.
- Триггеры: `avi:jira:commented:issue`, `avi:jira:deleted:comment`, `avi:forge:installed:app` (старт backfill).
  События на правку комментария в Forge нет.
- Значение пишется через `PUT /rest/api/3/app/field/{fieldId}/value?generateChangelog=false`,
  в backfill — одним запросом на пачку (значения сгруппированы).
- ID поля ищется по `schema.custom`, оканчивающемуся на `/static/last-comment-field`.
- Комментарии с `visibility` и внутренние JSM (`jsdPublic === false`) пропускаются — не допустить утечки.
  Включаются только явной настройкой админа `includeRestricted`.
- Backfill: очередь `backfill-queue`, цепочка событий (проект → страницы по 50 через `/rest/api/3/search/jql`),
  состояние в KVS `backfill-state`, 429 → `InvocationError` с `retryAfter`.
- Настройки: KVS `settings`, страница `jira:adminPage` (UI Kit, `useAsConfig`).
- Проверено: `npm run check` — tsc, юнит-тесты, сценарии на эмуляции Jira/KVS/очереди
  (`node:test` + module mocks), манифест против JSON-схемы @forge/manifest.
  `forge lint` / `deploy` ещё не запускались (нужна авторизация) — эмуляция не заменяет живую проверку.
