# Last comment field (Jira Cloud, Forge)

Read-only поле с текстом последнего публичного комментария.

## Возможности (v0.3)
- Поле обновляется при добавлении и удалении комментария.
- **Поля для JSM** (заполняются только в проектах Jira Service Management):
  - `Last customer reply`: дата и время последнего комментария клиента;
  - `Last agent reply`: дата и время последнего публичного ответа агента;
  - `Last reply by`: `Customer` или `Agent`.

  Агент — тот, у кого в проекте есть право агента (`SERVICEDESK_AGENT`), остальные — клиенты.
  Внутренние заметки, закрытые комментарии и комментарии приложений и автоматизации ответами
  не считаются, настройка учёта закрытых комментариев на эти поля не влияет.
- Закрытые комментарии (видимость группе/роли) и внутренние заметки JSM не попадают в поле,
  если админ явно не включил это в настройках. Если последние комментарии закрытые,
  ищется более ранний публичный (постранично, до 10 000 комментариев).
- **Заполнение старых задач (backfill)**: запускается само при установке и вручную со страницы
  админа. Идёт через очередь Forge: одно событие = 50 задач одного проекта, по одной пачке за раз,
  при 429 от Jira пачка повторяется через `Retry-After`. Прогресс и отмена — на странице админа.
- **Страница настроек** (Jira settings → Apps → Last comment field): максимальная длина (20–255),
  дата и автор в начале текста, учёт закрытых и внутренних комментариев (с предупреждением).

## Устройство
| Файл | Что делает |
|---|---|
| `src/core.ts` | Чистая логика: ADF → текст, обрезка, фильтр видимости и ответов, формат, валидация настроек |
| `src/jira.ts` | REST Jira: поиск ID полей, тип проекта, проверка агента, комментарии постранично, пакетная запись, поиск задач |
| `src/backfill.ts` | Запуск, обработка пачки, отмена, состояние в KVS |
| `src/settings.ts` | Настройки в KVS |
| `src/index.ts` | Точки входа: триггеры, consumer очереди, резолвер админки |
| `src/frontend/index.tsx` | Страница админа (UI Kit) |

## Запуск
```bash
npm i -g @forge/cli
forge login            # email + API token: https://id.atlassian.com/manage-profile/security/api-tokens
npm install
forge register         # подставит app.id в manifest.yml
forge lint
forge deploy
forge install          # выбрать свой dev-сайт и Jira
```
Добавь поле «Last comment» на экран задачи, оставь комментарий, смотри `forge logs`.

## Очереди JSM
Время с последнего ответа считает сам JQL через относительные даты. Примеры для очереди проекта:
```
# Клиент ждёт ответа дольше 4 часов, самые давние сверху
"Last reply by" ~ Customer AND "Last customer reply" <= -4h ORDER BY "Last customer reply" ASC

# Мы ответили, клиент молчит больше 3 дней
"Last reply by" ~ Agent AND "Last agent reply" <= -3d
```
У новой заявки без комментариев поля пустые: `"Last reply by" IS EMPTY`.

npm run check   # tsc + юнит-тесты + сценарии на эмуляции Jira/KVS/очереди + манифест по JSON-схеме

## Известные ограничения
- Правка комментария не обновляет поле: в Forge нет события на редактирование комментария.
- Смена настроек применяется к новым комментариям; для старых задач — перезапустить backfill.
- Backfill пишет значение и в задачи без комментариев (`null`), чтобы после смены настроек
  не оставались устаревшие значения.
- Поля JSM пишутся только в задачи проектов JSM: при переносе задачи в другой проект старые
  значения остаются. Если человека сделали агентом или убрали из агентов, старые задачи
  пересчитает backfill.
